性能优化：让壁纸在不需要动的时候停下来（省电降温）

问题
  用户反馈跑这个壁纸电脑会发热。查下来不是"某一帧太慢"，
  而是**它永远在满速跑** —— 没听歌、屏幕被窗口盖住、甚至息屏了也在画。

  根因有三处：
    · main.mjs 里写着 backgroundThrottling: false（"壁纸要一直动，别被节流"）
    · 没有任何 visibilitychange / powerMonitor 的暂停逻辑
    · 频谱是**正弦模拟**的，不依赖真实音频，所以歌停了它照样在动

测量（走了一些弯路，都记在工具注释里）
  ✗ 一开始拿"界面 rAF 帧率"当指标 —— 冻住动画后帧率反而从 101 涨到 230。
    那个数字测的是合成器循环速度，不是负载。
  ✗ 又试了 Windows 的 GPU Engine 计数器 —— 恒报 ~50%，改状态都不动，不可信。
  ✓ 最后用**进程 CPU 时间增量**（拆到 renderer / gpu-process），稳定可比。

  实测（平均占用核数，renderer + gpu-process）：
    基线全开            3.15 核
    关掉壁纸视频         省 0.83 核（26%）  ← 最大头
    关掉频谱            省 0.40 核（13%）
    关掉 blur/grain/vignette   ≈0            ← 和直觉相反，这些几乎不花钱

改动
  src/build-player-ui.mjs
    · 新增节流器：按状态分档 —— 播放中全速 / 暂停降到 12fps / 遮挡息屏完全停
    · 频谱循环在非播放状态直接跳过（它本来就不依赖音频）
    · **用 animation-play-state 冻住 CSS 动画**。
      光停 rAF 没用：试过之后界面照样跑 158fps，因为 CSS 动画在合成器线程上。
    · 壁纸视频只在"播放中 + 可见"时解码（loop 动图白烧了 26% 的 CPU）
    · 日夜两个 video 只让可见的那个播（原来两个都在解码）
    · 帧率上限 60（屏幕是 85Hz，多画的那 25 帧看不出来）

  desktop/main.mjs
    · powerMonitor 监听挂起/恢复/锁屏/解锁 → postMessage 通知界面停机
    · 新增 --debug-port=N 开关（排查用，平时不开）

验证（desktop/tools/verify-throttle.mjs）
  播放中   3.288 核   基线
  暂停     2.252 核   ↓32%
  息屏     0.892 核   ↓73%

  频谱重画频率（count-vizcalls.mjs）：
  播放中 48 帧/秒   暂停 0   息屏 0   恢复 48

  "保留所有元素"这条是满足的：不隐藏、不删除、不改布局，
  只是把动画停在当前姿态 —— 可见时和在跑时视觉完全一致。

新增排查工具
  verify-throttle.mjs   量各状态的 CPU 开销（最可靠的省电验证）
  cpu-breakdown.mjs     拆到进程级看谁在烧
  ablate-layers.mjs     逐个关掉视觉层，量各自成本
  count-vizcalls.mjs    数频谱的真实重画频率
  check-fpscap.mjs      确认帧率上限生效
  measure-live.mjs      连真实进程量帧耗时
  inspect-videos.mjs    看 video / 合成层 / 在跑的动画

  删掉两个不可靠的：bench-heat / bench-idle（在隐藏窗口里测，
  Chromium 把 rAF 节流到 1fps，数字全是假的）
