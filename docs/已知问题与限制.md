# 已知问题与限制

按"会不会影响正常使用"排序。

---

## 影响体验的

### 1. 律动频谱不是真频谱

**现象**：时钟下方那排起伏的柱子，跟音乐节奏**没有真实关联**。

**原因**：拿不到 QQ 音乐的音频流。声音从 QQ 音乐直接进声卡，
不经过浏览器；浏览器也没有系统级音频捕获能力。

**现在的做法**：三组不同频率/相位的正弦叠加，模拟出自然的起伏，
播放时有律动、暂停时压平、切歌时从左扫过一道脉冲。视觉上够用。

**如果要做真的**：需要 WASAPI 环回采集（loopback capture），
用 Python/C# 起一个后台进程抓系统音频，做 FFT 后把频谱数据推给页面。
代价明显更大（多一个常驻进程 + 音频权限），当时没做。

**相关代码**：`src/build-player-ui.mjs` 里的 `vizFrame()`

### 2. 拖动 QQ 音乐进度条后，歌词会偏

**现象**：把 QQ 音乐的进度条拖到中间，界面上的进度和歌词还在原来的位置附近。

**原因**：QQ 音乐**不通过 SMTC 上报播放位置**（`Position` / `EndTime` 恒为 0）。
也试过 UIAutomation 读 QQ 音乐的进度条节点，读不到。
所以位置只能靠"开始播放时刻 + 单调时钟"推算。

**缓解**：设置面板里有"歌词对齐"（−1s / 0s / +1s），可手动补偿。

**相关代码**：`overlay/src/server.mjs` 里的合成时钟（`clockPosition` 等）

### 3. 短时间疯狂切歌会有几首歌暂时没歌词

**现象**：连续快速切歌时，偶尔有几首显示"这首歌暂时没有同步歌词"。

**原因**：QQ 音乐搜索接口对**突发频率**很敏感。但**两个接口的限流表现不一样**：

| 接口 | 角色 | 限流时的表现 |
|---|---|---|
| `client_search_cp` | **主** | **HTTP 500** |
| `musicu.fcg` | 备 | HTTP 200 + `code=2001`（数据为 null） |

早先只认出了后一种，把前一种的 500 当成"接口已废弃"——
这个误判让代码长期用了一个**更脆弱**的接口当主力（实测 1 秒间隔下只有 5/10，
而"废弃"的那个是 10/10）。2026-09 已纠正，顺序反过来了。

**已做的缓解**：
- **两种限流都识别**（HTTP 非 200 和 `code != 0` 都算限流）
- 请求闸门：所有搜索排队，两次之间最少隔 3 秒
- 限流后整体冷却 60 秒（不试探，越试越糟）
- **失败自动补取**：每 25 秒重试一次，冷却结束自动补上

正常听歌（一首歌 3-4 分钟才查一次）完全不会触发。**这个只能规避，没法根治。**

**相关代码**：`overlay/src/lyrics.mjs` 的 `gate()` / `ThrottledError` / `breaker`

**排查工具**：`node --use-system-ca overlay/tools/probe-apis.mjs`
（会分别报告两个接口的状态，并把限流和故障区分开）

### 4. 有些歌确实没有歌词

**现象**：少数歌显示"这首歌暂时没有同步歌词"。

**原因**：QQ 音乐对这些歌只给纯文本歌词（没有时间戳），或者压根没歌词。
这不是 bug。纯文本歌词会退化成"不跟唱、只显示一段"。

## 不影响使用但要知道的

### 5. 歌名太长会缩到很小

超过可用宽度时自动缩字号，**最小缩到原字号的 50%**（70px → 35px）。
再长就交给省略号。这是有意的取舍：宁可字小也要显示全，比截断好看。

### 6. 只有竖版壁纸

方版壁纸（`suzuran_yukihare_square.mp4`）做出来过，后来删了——
竖版能看到神社台阶和鸟居，构图留白更舒服。

### 7. 壁纸是循环短片，不是完整原片

原片 52 秒、69MB。裁出白天（17s）和夜晚（21s）两段各自循环，
压到 810×1080 / CRF 23，共 8.7MB。看不出接缝。

### 8. 只支持 QQ 音乐

`session-watch.ps1` 默认按 `QQMusic` 过滤会话。
理论上改 `-App` 参数能读别的播放器，但**歌词源和封面源都是 QQ 音乐的**，
换播放器得另找接口。

### 9. 歌词接口随时可能变

QQ 音乐的接口不是公开 API，什么时候改都正常。
**如果突然所有歌都没歌词**，先跑诊断：

```powershell
node overlay\tools\probe-apis.mjs
```

它会挨个试几个接口变体，直接告诉你哪个还能用。

## 已经踩过并修好的坑（留档，别再踩）

这些写在 `docs/架构与技术决策.md` 里有完整说明，这里只列清单：

| 坑 | 后果 | 修法 |
|---|---|---|
| `-webkit-text-stroke` + `paint-order` | 描边不出来 | 改 `text-shadow` 八向环绕 |
| `.ps1` 没有 UTF-8 BOM | PowerShell 5.1 按 ANSI 读，中文注释里的引号被吃掉，**整个脚本语法错误** | 全部 `.ps1` 必须带 BOM |
| PowerShell `Write-Output` 输出 JSON | 中文经管道重新编码变乱码 | 改用 `[Console]::Out.WriteLine` |
| PowerShell `-Raw` 往返 | 吃掉换行 + 产生 mojibake | 用编辑工具改源码，别用 shell 往返 |
| 客户端 bundle 的 `id` 用了主题 id | 加载器报错 + 白屏 | `id` 必须是包名 |
| 客户端插件 `FONTS[scheme]` 为 undefined | `Object.entries(undefined)` 抛错 | 加 `?? FONTS.light` 兜底 |
| flex 子项宽度被压到"最长子项宽" | 歌名只拿到 370px（应 404px），自动缩字误判 | 改 grid + `minmax(0, 1fr)` |
| flex 子项光有背景没内容 | 高度被压成 0，柱子看不见 | 显式 `height: 100%` |
| `--w` 挂在 `.right` 上 | 表情按钮在 `body` 下取不到，宽度算成 0 | 挂到 `:root` |
| `mix-blend-mode: screen` 在浅色底 | 颜色被推向白色，效果完全看不见 | 先铺深底再叠光团 |
| `.right` 上加了 `z-index: 1` | 创建层叠上下文，里面的 `.fx`(z-index:0) 跑到整个界面下面 | `.right` 不加 z-index，靠内容块自己带 z-index:1 |
| 设置面板竖排 370px 高 | 挂哪都撞东西（右上压歌名、右下压日期） | 改成 2×2 横版 404×182，放进右下角空白区 |
| 构建脚本里模板字符串嵌套反引号 | `SyntaxError` | 改字符串拼接 |
| `.bat` 用中文名 + `cmd /c "名.bat"` | 报 "not recognized" | 用 ASCII 名 + 桌面快捷方式 |
| `session-watch.ps1` 里 `BitConverter`/`Utf8` 弯路 | 白折腾 | 见下条 |

### 关于 PowerShell 读 WinRT 缩略图

最终没走通，改用搜索接口。但过程里的两个教训值得记：

1. **不能调 `$ras.Dispose()`**——PowerShell 拿到的是 `__ComObject`，没这个方法，
   抛异常还会把整个读取拖失败
2. **WinRT 类型必须显式预加载**，否则脚本里引用会报"找不到类型"：

```powershell
$null = [Windows.Graphics.Imaging.BitmapDecoder, Windows.Graphics.Imaging, ContentType = WindowsRuntime]
```
