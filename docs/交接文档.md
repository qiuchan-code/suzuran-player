## 一、这是什么

一个樱花粉主题的桌面音乐播放器界面。核心能力：**读 Windows 的媒体会话（SMTC），
识别 QQ 音乐正在播放的歌，实时抓歌词并跟唱**，配《明日方舟》铃兰的动态壁纸。

关键点：**这不是播放器**。它不控制 QQ 音乐，也不读音频流，只是"看着"QQ 音乐在放什么，
然后把信息漂亮地显示出来。

**两种运行形态**：

| 形态 | 入口 | 说明 |
|---|---|---|
| **桌面壁纸模式** | `desktop/launch-desktop.vbs` | 界面挂在 Windows 桌面层（`WorkerW`），替代 Wallpaper Engine。见 `desktop/README.md` |
| 浏览器模式 | `start-player.bat` | 开浏览器窗口，`http://127.0.0.1:7790/player-ui.html` |

两者共用同一套服务（歌词 :7788 / 界面 :7790）和同一个 `player-ui.html`。

## 三、工程坑（**最重要的一节**）

这一节是踩过的坑和根因。**碰相关代码前先看这里**，能省大量时间。

### 3.1 关于渲染

| 坑 | 现象 | 根因 | 正确做法 |
|---|---|---|---|
| `-webkit-text-stroke` 描边不出来 | 白描边被字面盖住 | Chrome 里 `paint-order` 救不回来 | 用 `text-shadow` **八向环绕**，见 `ringShadow()` |
| `mix-blend-mode: screen` 在浅色底 | 效果完全看不见 | 滤色把颜色推向白色 | 先铺**深色底**再叠光团 |
| 分栏伪元素造成竖线 | 左栏右缘一条硬边 | `.left::before/::after` 是**按栏**渲染的，渐变到 100% 是实色，到栏边界突然结束 | 改成**铺满整卡**的一层（`.vignette`），没有"到某处突然结束"的边界 |
| 壁纸遮罩被栏裁断 | 同样一条竖线 | 壁纸放在 46% 宽的栏里，椭圆到边界只衰减到 0.5 | 画面容器保持 46% 宽（保证裁切比例），**遮罩挂到卡片级别**（`.hero`） |
| flex 子项宽度被压到"最长子项宽" | 歌名只拿到 370px（应 404px） | flex 的 min-content 行为 | 改 `display: grid` + `minmax(0, 1fr)` |
| flex 子项光有背景没内容 | 高度被压成 0，柱子看不见 | flex 不给你撑高 | 显式 `height: 100%` |
| `--w` 挂在 `.right` 上 | 右下角按钮宽度算成 0 | 按钮在 `body` 下，不在 `.right` 里 | 变量挂 `:root` |
| `.right` 上加了 `z-index` | 里面的绝对定位层跑到最底下 | 创建了层叠上下文 | 别在容器上加 z-index，靠内容块自己带 |
| 重复的 CSS 规则块 | 新规则不生效（字号退回 16px） | 编辑时留下了**两个 `:root` 块** | 改完 grep 一遍同名选择器 |
| CSS 序列化丢 `circle` | 正则提取半径永远失败 | `el.style.maskImage` 读回来是 `radial-gradient(300px at ...)`，`circle` 被省略 | 别从 `style` 读值，用 `getComputedStyle` |

### 3.2 关于脚本环境

| 坑 | 现象 | 根因 | 正确做法 |
|---|---|---|---|
| **`.ps1` 没有 UTF-8 BOM** | PowerShell 5.1 按 ANSI 读，中文注释里的引号被吃掉 → **整个脚本语法错误** | PS 5.1 不用 BOM 猜编码 | **所有 `.ps1` 必须带 BOM**（这个坑踩了 4 次） |
| `Write-Output` 输出 JSON | 中文乱码 | 管道会重新编码 | 用 `[Console]::Out.WriteLine` |
| PowerShell `-Raw` 往返文件 | 吃掉换行 + 产生 mojibake | 编码转换有损 | 用编辑工具改源码，别用 shell 往返 |
| `.bat` 用中文名 | `cmd /c "中文名.bat"` 报 not recognized | codepage 问题 | ASCII 文件名 + `.lnk` 快捷方式用中文 |
| Node fetch 报 `UNABLE_TO_VERIFY_LEAF_SIGNATURE` | 取不到网络数据 | 证书链 | 加 `--use-system-ca` |
| bsdtar 解 npm 包 | "Cannot connect to D:" | 把 `D:\...` 当 host:path | 切 cwd + 相对路径 |

### 3.3 关于桌面壁纸模式

**完整的一组坑单独写在 `desktop/README.md`**，这里只列最容易再犯的三条：

| 坑 | 现象 | 根因 | 正确做法 |
|---|---|---|---|
| **`spawnSync` 死锁** | 调挂载脚本时 PowerShell 卡住永不返回 | `spawnSync` 阻塞 Electron 主线程，而 `SetParent` 需要目标窗口线程处理同步消息 → 互相等死 | 必须用**异步** `spawn` |
| **可选链吞掉错误** | 悬浮条能拖但播放器毫无反应，**不报错** | 页面里写 `window.dsh?.tier(i)`，而 `window.dsh` 从未定义；`?.` 遇到 undefined **静默跳过** | 跨进程桥接**不要用可选链兜底**，宁可让它抛错 |
| **`.vbs` 必须纯 ASCII** | 脚本完全不执行 | VBScript 按 ANSI(GBK) 解码，UTF-8 中文注释变乱码，**乱码字节把换行也吞了** | `.vbs` 纯 ASCII + CRLF（和 `.ps1` 必须带 BOM 正好相反） |

### 3.4 关于 CDP 测试（我踩得最多，也最容易骗到自己）

| 坑 | 现象 | 根因 | 正确做法 |
|---|---|---|---|
| **测到了 Chrome 错误页** | 得出"DOM 结构不对"的错误结论 | 批量杀 node 进程时把静态服务器也杀了，脚本还在跑 | 测前先验证页面真的加载了：`document.body` 里应该有 `.card`，**不该有 `#content` / `#offline-resources`** |
| `document.querySelector('.trackTitle')` 命中快照副本 | 误判"两层颜色相同" | 快照挂在 `#reveal` 里，而 `#reveal` 在 DOM 顺序上比 `.right` 靠前 | 用 `closest('#reveal')` 排除，或用 `elementsFromPoint` |
| `captureScreenshot` 截出小长条 | 验证图尺寸不对 | **默认 `captureBeyondViewport: true`**，传 clip 会去视口外取图，坐标解释变了 | 显式 `captureBeyondViewport: false`，clip 夹紧到视口内 → 用 `src/tools/lib/cdp-shot.mjs` |
| 量像素带里混进文字/噪点 | "全程最大跳变 34"这种噪声 | 测量带里有点阵纹理或文字 | 先把干扰层关掉，或加中值滤波 |
| 采样起点太晚 | 错过快照刚建立的那段 | 快照在 ~50ms 就建好了，我从 200ms 才开始采 | 采样器要在**触发之前**装好 |

### 3.5 关于主题切换（花了一整轮才查清）

**症状**：只有铃兰附近能看到切换痕迹，右侧看不到扩散。

**排查过程**（走了很多弯路，留档）：
1. 先怀疑 `mask-image` 不支持 → 实测支持
2. 再怀疑遮罩半径是 0 → **错**，是我的正则匹配不到（CSS 丢了 `circle`）
3. 再怀疑快照没冻结 → **错**，实测 35 个样本两层颜色全部不同
4. 最后截图看 → **扩散一直是正常的**

**真正的问题**有两层：
- **快照没有冻结主题**：主题变量写在 `<body>` 上，快照也挂在 `<body>` 下，
  `applyTheme()` 一改 body 变量，快照立刻跟着变 → "新主题推开新主题"，看不出变化。
  **修法**：把当前主题变量以**行内样式**写到快照根节点上（行内优先于继承）。
- **遮罩过渡带 90px 太宽** + **快照底色用了半透明变量** → 新旧两层在宽带上糊在一起。
  **修法**：边缘收到 14px；底色取 `bodyCS.backgroundColor`（不透明）。

**当前实现**见 `revealTheme()`：
```
1. 克隆 .card 做快照
2. 把当前主题的 CSS 变量写成快照的行内样式（冻结）
3. 立刻 applyTheme() 切底下真页面
4. 逐帧用 radial-gradient 遮罩把"洞"扩大，洞内露出新页面
5. 结束删快照、恢复实时动效
```

## 五、限制（改不掉的，别浪费时间）

| 限制 | 原因 |
|---|---|
| **律动频谱不是真的** | 拿不到 QQ 音乐的音频流（声音不经过浏览器）。现在是正弦叠加的拟态。要做真的得用 WASAPI 环回采集 + 独立进程做 FFT |
| **进度是推算的** | QQ 音乐不通过 SMTC 上报位置（恒为 0），也读不到 UIAutomation 进度节点。拖动进度条后界面会偏 |
| **歌词接口会限流** | 超频返 `code=2001`（HTTP 200 但数据 null），约 1 分钟冷却。已做 3 秒请求闸门 + 失败自动补取 |
| **有些歌确实没歌词** | QQ 音乐只给纯文本（无时间戳）或压根没有。纯文本会退化成"不跟唱" |
| **只支持 QQ 音乐** | 会话读取能换 `-App`，但歌词源和封面源都是 QQ 音乐的 |
| **歌词接口随时可能变** | 不是公开 API。出问题先跑 `overlay/tools/probe-apis.mjs` |
| **桌面壁纸模式内存偏高** | 1500-1600 MB。已排除泄漏和单点特性，744 MB 固定开销来源未定位 |

## 六、还能做什么（可选方向）

按价值排序：

1. **查桌面壁纸模式的 744 MB 固定开销** —— 唯一没解决的技术问题。
   建议方向：`--disable-gpu-compositing` 对比、换 D3D11/OpenGL 后端、
   用 CDP 的 `Memory.getDOMCounters` 看层数。如果查不出来，
   **退路是做"极简壁纸模式"（实测只要 367 MB）**：壁纸层只放背景 + 落雪，
   界面另开窗口
2. **把两个服务合成一个进程** —— 现在是 7788（歌词）+ 7790（界面+代理），
   可以只留一个 HTTP 服务，少一个端口、少一层代理
3. **真频谱** —— WASAPI 环回采集 + FFT，能做出真正的音乐律动
4. **歌词缓存持久化** —— 现在缓存在内存，重启就没了
5. **多播放器支持** —— 加网易云 / Spotify 的歌词源
6. **壁纸做成可切换列表** —— `assets/wallpaper/` 里还能放更多素材
